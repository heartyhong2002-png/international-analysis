# 국제정세 분석 조기경보 프로그램 지도교수 면담 자료

**작성 목적**  
한국공학대학교 데이터사이언스경영전공의 개인 포트폴리오 또는 캡스톤 연계 프로젝트로서의 적합성, 범위, 검증 방법에 대해 지도교수님의 조언을 받기 위한 자료입니다.

**프로젝트 성격**  
이 프로젝트는 국제정세를 단정적으로 예측하거나 미확인 정보를 뉴스처럼 전달하는 시스템이 아닙니다. 공개된 여러 데이터에서 평소와 다른 변화가 나타나는지 탐지하고, 출처와 검증 상태를 함께 보여주는 OSINT 기반 지정학·공급망 리스크 조기경보 프로토타입입니다.

**현재 판단**  
수집기, 전처리·분류, 신호 결합과 교차검증, 데이터베이스 적재, HTML 대시보드, 보고서 생성까지의 프로토타입은 구현되어 있습니다. 금융시장 이벤트 스터디, 고도화된 토픽 모델링, RAG 리포트 자동화, 장기 운영 검증은 향후 계획입니다.

### 향후 계획

- 핵심 감시축과 소스를 축소해 정기적으로 수집되는 최소 운영 세트를 확정합니다.
- 출처별 수집 성공률, 결측률, 중복률, 지연시간을 지표화합니다.
- 골드셋을 만들고 이슈 태깅·검증 상태·위험도 점수의 정확도와 일관성을 평가합니다.
- 위험도 점수는 실험적 지표로 운영하고, 공식 예측 확률이나 투자 신호로 표현하지 않습니다.
- 토픽 모델링·임베딩·RAG·금융시장 이벤트 스터디는 핵심 파이프라인 안정화 이후 단계적으로 적용합니다.

## 4. 데이터 전처리 및 신뢰도 관리

1. **중복 제거**: URL·제목·본문 해시와 유사도 기준을 조합해 동일 기사 재전파와 RSS 중복을 줄입니다.
2. **날짜·시간 통일**: 원문 시각, 발행 시각, 수집 시각을 UTC 기준으로 저장하고 화면에서 한국시간으로 변환합니다.
3. **언어 감지·번역**: 원문 언어를 보존한 뒤 분석용 공통 필드만 번역·정규화합니다. 번역문을 원문과 동일한 사실로 취급하지 않습니다.
4. **국가·지역 태깅**: 국가명·수도·기관·지명 사전과 규칙을 사용하고, 애매한 경우 `ambiguous`로 남깁니다.
5. **이슈 카테고리 분류**: 동아시아, 러시아·우크라이나·유럽, 미·동맹, 미·중 기술·무역, 중동 에너지·해운 등 5대 감시축과 세부 이슈를 병행합니다.
6. **출처별 신뢰도 등급**: 출처의 신뢰도와 개별 주장 확인 여부를 분리합니다. 기관 등급이 높아도 개별 주장 자체가 자동 확정되는 것은 아닙니다.
7. **공식 자료와 교차검증**: 공식 발표, 독립 언론, 현지 공개 신호, 행동·시장 신호가 같은 사건을 가리키는지 비교합니다.
8. **루머·허위정보 표시**: `reported`, `unverified`, `information_gap`, `corroborated`, `refuted` 등 상태와 검증 이력을 함께 표시합니다.
9. **SNS·Telegram 처리**: 국민 전체 여론이나 확정 사실이 아니라 ‘온라인 정보환경에서 관측된 초기 신호’로만 사용합니다. 단일 게시물은 경보 점수를 올리지 않습니다.

## 5. 위험도 점수화 아이디어

아래는 공식 예측모델이 아닌 **초기 설계안·실험적 점수화 방식**입니다. 실제 적용 전에는 과거 사례와 사람 검수로 조정해야 합니다.

### 제안 구조

각 이슈에 대해 0~100 범위의 `Risk Signal Score`를 계산하고, 점수와 별도로 검증 상태와 데이터 품질을 표시합니다.

`Risk Signal Score = 0.20×증가율 + 0.15×급증성 + 0.15×출처 다양성·신뢰도 + 0.15×공식 확인 + 0.15×교차검증 + 0.10×지역·국가 중요도 + 0.05×과거 유사도 + 0.05×금융·공급망 영향 가능성`

- **증가율**: 기준기간 대비 키워드·기사·검색량 변화
- **급증성**: 짧은 기간의 비정상적 언급량 상승 여부
- **출처 다양성·신뢰도**: 서로 독립적인 출처가 참여했는지
- **공식 확인**: 정부·국제기구 자료와의 일치 또는 공식 발표 존재
- **교차검증**: 서로 다른 센서가 같은 사건을 가리키는지
- **지역·국가 중요도**: 한국 공급망·외교·안보와의 연결성
- **과거 유사도**: 과거 사례와의 텍스트·패턴 유사성
- **금융·공급망 영향 가능성**: 해운·에너지·무역·시장 경로의 존재

점수는 다음처럼 표현할 수 있습니다.

| 점수 | 표현 | 의미 |
|---:|---|---|
| 0–24 | 관찰 | 변화가 작거나 근거가 부족함 |
| 25–49 | 관심 | 추가 확인할 가치가 있는 신호 |
| 50–74 | 검토 필요 | 여러 신호가 함께 움직여 사람이 검토해야 함 |
| 75–100 | 우선 검토 | 강한 신호가 결합되었으나 사건 확정이나 예측을 의미하지 않음 |

운영 시에는 점수만 보여주지 않고 `왜 올라갔는지`, `어떤 출처가 부족한지`, `마지막 관측 시각`을 함께 제공합니다. 데이터가 부분 수집이거나 단일 SNS 신호뿐이면 점수 상한을 두는 것도 고려할 수 있습니다.

## 6. NLP·텍스트마이닝 적용 방향

| 단계 | 적용 내용 | 기술 스택 예시 |
|---|---|---|
| 1단계 키워드 빈도 | 이슈별 언급량, 증가율, 검색량 추이 | Python, pandas, 정규식, SQL |
| 2단계 태깅 | 국가·지역·기관·이슈 카테고리 추출 | 사전·규칙, spaCy, KoNLPy, API |
| 3단계 위험 표현 | 긴장·봉쇄·제재·공격 등 표현 탐지와 감성 보조지표 | transformers, multilingual models, LLM |
| 4단계 토픽 모델링 | 기사·게시물의 잠재 주제와 시간별 변화 | scikit-learn, BERTopic, sentence-transformers |
| 5단계 클러스터링 | 같은 사건을 다룬 뉴스·SNS 묶음과 확산 경로 비교 | 임베딩, cosine similarity, HDBSCAN, DBSCAN |
| 6단계 LLM 요약 | 근거 문장과 불확실성을 보존한 이슈 요약 | LLM, 구조화 JSON 출력, 원문 링크 |
| 7단계 RAG 리포트 | 검증된 문서만 검색해 근거형 보고서 생성 | 벡터 DB, embedding, RAG, SQL/metadata filter |
| 8단계 금융 연결 | 사건 전후 수익률·변동성·거래량·환율·원자재 비교 | pandas, yfinance/공개 API, statsmodels, 이벤트 스터디 |

실행 순서는 1~3단계의 품질을 먼저 확보한 뒤 4~8단계로 확장하는 것이 적절합니다.

## 9. 주식분석 프로그램과의 연계 가능성

확장 주제는 **“국제정세 리스크가 금융시장에 미치는 영향 분석 시스템”**입니다.

- 지정학 이벤트의 발생·공식 확인·검증 완료 시점을 주가, ETF, 환율, 원자재 시계열과 연결합니다.
- 이벤트 전후 1일·5일·20일 수익률, 변동성, 거래량을 비교합니다.
- 반도체·방산·에너지·해운·원자재·환율 관련 자산을 감시군과 연결합니다.
- 동일 유형의 과거 이벤트를 모아 평균 효과와 분산을 계산합니다.
- 이벤트 스터디, 시장모형, 단순 회귀를 사용해 관련성을 탐색합니다.
- 결과는 투자 추천이 아니라 지정학 리스크와 자산 반응을 관찰하는 보조 지표로 표현합니다.

금융 연결은 데이터 정합성과 사건 시점 정의가 중요하므로, 조기경보 MVP가 안정화된 뒤 한두 개 이슈와 소수 자산으로 시작하는 것이 적절합니다.

## 10. 포트폴리오용 README 초안

### 프로젝트 소개

국제정세와 공급망 관련 공개 데이터를 수집·정리해 위험 신호의 변화와 출처 간 불일치를 보여주는 조기경보 분석 프로토타입입니다. 미래 사건을 단정적으로 예측하는 서비스가 아니라, 사람이 추가 확인할 이슈를 찾는 리스크 모니터링 도구를 목표로 합니다.

### 개발 배경

국제정세 정보가 공식 발표, 뉴스, 현지 공개 커뮤니티, 시장·물류 지표에 흩어져 있다는 문제에서 출발했습니다. 초기에는 사건 예측을 목표로 검토했지만 검증 기준과 실패 정의가 복잡하다는 점을 확인하고, 관측 가능한 신호와 검증 상태를 제공하는 조기경보 방향으로 전환했습니다.

### 문제 정의

단일 출처는 빠르지만 노이즈가 크고, 공식 자료는 신뢰성이 높지만 지연될 수 있습니다. 여러 출처를 동일한 구조로 저장하고 비교해 “무엇이 확정되었는가”와 “무엇을 더 확인해야 하는가”를 분리합니다.

### 주요 기능

공개 데이터 수집, 국가·지역·이슈 태깅, 신호 집계, 교차검증 상태 관리, MySQL 적재, HTML 대시보드, PDF·DOCX 보고서 생성, 모델 합의·사람 검수용 실험 도구를 포함합니다.

### 사용 기술

Python, pandas, RSS/API, SQL/MySQL, 다국어 LLM, scikit-learn 계열 분석, HTML/Streamlit 시각화, PDF·DOCX 생성 도구를 사용합니다.

### 데이터 출처

GDELT Cloud, 뉴스·정부 RSS, 국제기구 및 공공 API, 공개 Telegram·Reddit·SNS/포럼, Google Trends, 여론조사, 해협·항만·무역·금융 프록시, 싱크탱크·정책연구기관 자료입니다.

### 데이터 신뢰도 관리 방식

원문·URL·시각·출처 유형을 저장하고, `unverified`, `partially_confirmed`, `cross_verified`, `refuted` 등의 상태를 구분합니다. SNS·Telegram·Reddit은 확정 사실이 아니라 초기 신호로만 사용합니다.

### 위험도 점수화 방식

언급량 증가, 출처 다양성, 공식 확인, 교차검증, 국가·공급망 중요도 등을 결합한 실험적 점수입니다. 공식 예측 확률이나 투자 추천으로 해석하지 않습니다.

### 실행 화면 예시

대시보드는 5대 감시축을 균형 있게 보여주고, 각 경보 후보에 검증 상태·근거 수·마지막 관측 시각·데이터 품질을 함께 표시합니다.

### 향후 개선 계획

골드셋 구축, 태깅 평가, 토픽·문서 클러스터링, RAG 리포트, 알림 운영, 금융시장 이벤트 스터디, 장기 백테스트를 단계적으로 수행합니다.

### 배운 점

비정형 데이터 파이프라인, 관계형 DB, 다국어 텍스트 처리, 모델 검증, 시각화, 프로젝트 범위 관리와 데이터 윤리를 학습했습니다.

### 한계점

소셜 데이터의 대표성 부족, 언어·지역 편향, 소스 차단과 결측, 사건 라벨의 모호성, 위험도 점수의 실험적 성격이 있습니다.

### 윤리적·법적 주의사항

공개 데이터와 허용된 API만 사용하고, 비공개 정보·개인 식별정보·로그인 우회·저작권 침해를 피합니다. 검증되지 않은 내용을 사실처럼 게시하지 않고, 원문 링크와 한계를 표시합니다.
