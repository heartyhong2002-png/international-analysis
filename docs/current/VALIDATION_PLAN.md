# 조기경보 검증 계획

## 1. 검증 관점

이 시스템은 미래 사건 발생 여부를 직접 예측하지 않는다. 따라서 검증 질문도 "사건을 맞혔는가"가 아니라 "위험 신호를 근거 기반으로 일관되게 포착했는가"로 둔다.

## 2. 검증 방법

### 과거 사례 백테스트

우크라이나 전쟁, 대만해협 긴장, 미중 관세 갈등, 이란 핵협상 긴장, 중동 에너지 리스크처럼 이미 알려진 사례를 선정한다. 사건이 커지기 전 기간의 뉴스량, 논조, 정부 발표, 독립 언론, 금융 지표를 넣고 시스템이 Watch 또는 Warning을 낼 수 있었는지 확인한다.

### 사람 표본 검수

경보가 발생한 샘플의 일부를 사람이 확인한다. 검수자는 경보 단계, 근거 문장, 출처 적합성, 과도한 해석 여부를 평가한다. 기존 `data/review_log.csv`와 `data/pending_human_review.csv`의 방식을 확장한다.

### 근거 품질 검증

경보마다 다음 항목을 확인한다.

- 어떤 데이터가 경보를 만들었는가?
- 정부 발표와 독립·현지 신호가 실제로 다르게 나타나는가?
- LLM 판단에 근거 문장이 붙어 있는가?
- 근거가 부족할 때 시스템이 "판단 불가" 또는 "확인 필요"로 표현하는가?

### 오탐·미탐 기록

경보가 떴지만 이후 위험이 확대되지 않으면 오탐 후보로 기록한다. 반대로 실제 위험이 커졌는데 경보가 없었으면 미탐 후보로 기록한다. 졸업작품에서는 완벽한 정확도보다 오탐과 미탐을 기록하고 개선할 수 있는 구조를 보여주는 것이 중요하다.

## 3. 평가 지표

| 지표 | 의미 |
|---|---|
| Alert Precision | 경보가 나온 사례 중 사람이 타당하다고 본 비율 |
| Missed Signal Count | 알려진 위험 사례에서 경보가 나오지 않은 횟수 |
| Evidence Coverage | 경보에 연결된 근거 출처의 충분도 |
| Human Agreement Rate | LLM 경보 판단과 사람 검수의 일치율 |
| Source Diversity | 공식·독립·대중·시장 신호가 얼마나 다양하게 포함되었는지 |
| False Alarm Log | 경보 후 실제 위험 확대가 확인되지 않은 사례 기록 |

## 4. 표현 원칙

리포트와 대시보드는 "발생한다", "확정적이다" 같은 단정 표현을 피한다. 대신 다음 표현을 사용한다.

- 위험 신호가 증가했다.
- Watch 단계로 상향할 근거가 있다.
- 공식 발표와 독립 신호 사이의 괴리가 커졌다.
- 데이터가 부족해 판단을 보류한다.
- 추가 확인이 필요하다.

## 5. 졸업작품 방어 논리

예측 시스템은 정답 정의와 장기 검증이 어렵다. 조기경보 시스템은 관측 가능한 신호의 변화와 근거 품질을 평가하므로 제한된 졸업작품 기간 안에서도 검증 가능하다. 이 프로젝트의 검증 대상은 미래를 맞히는 능력이 아니라, 위험 신호를 수집·분석·설명·검수하는 정보시스템의 완성도다.
