# 로컬 채팅 테스트 점검표 (Phase 1 / README 7-1번)

작성일: 2026-09-20 · 기준 코드: `chatbot_core/` 5개 파일 + `frontend/index.html` (v2)

이 표는 "로컬에서 실제 Ollama 응답이 나오는지, 그 응답이 쓸 만한지"를 한 번에 확인하기 위한 것이다. 순서대로 진행하고 마지막 6번 기록표를 채워서 가져오면, 그 결과를 보고 프롬프트/코드 수정을 제안할 수 있다.

---

## 0. 코드를 읽고 먼저 확인한 사실 (테스트 전에 알아둘 것)

1. **`mode`는 Ollama 호출이 성공했을 때만 `llm`이다.** 실패하면 예외를 잡아 `template_fallback`으로 바꾸고, 실패 이유를 응답 JSON의 `warnings`에 넣는다.
2. **프론트엔드(`index.html`)는 `warnings`를 화면에 안 보여준다.** 화면에는 "🟡 템플릿 폴백"만 뜬다. 이유를 보려면 `http://localhost:8000/docs`(Swagger)에서 `/chat`을 직접 호출하거나 아래 PowerShell 명령을 쓴다.
3. **챗봇이 쓰는 모델은 `mistral-nemo:latest` 하나다.** `CONSENSUS_MODELS[0]`이 첫 번째 모델이고, 한국어 기준 모델인 `exaone3.5:7.8b`는 세 번째라서 챗봇 응답에는 안 쓰인다.
4. **`.env`는 자동으로 읽히지 않는다.** `chatbot_core/`, `verify_model_consensus.py`, `verify_factcheck_api.py` 어디에도 `load_dotenv()`가 없다. `OLLAMA_HOST`, `GOOGLE_FACTCHECK_API_KEY`, `CHATBOT_MYSQL_*`를 `.env`에만 적어뒀다면 uvicorn에는 적용되지 않는다(PowerShell에서 `$env:이름="값"`으로 설정해야 한다).
5. **현재 `auto_benchmark_results.csv`의 4건은 샘플 데이터로 보인다.** 링크가 전부 `https://example.com/article-N`이다. 챗봇은 이걸 실제 기사(Reuters, National Review 등)처럼 출처로 인용한다.
6. **이슈를 못 찾거나 데이터가 0건이어도 LLM은 그대로 호출된다.** "데이터 없음"이라는 문구가 프롬프트에 들어갈 뿐이고, 지어내지 않는 건 모델이 규칙 1번을 얼마나 지키느냐에 달려 있다.

이 세션에서 직접 확인한 것: 의도 분류·데이터 검색 결과(아래 3번의 기대값), Ollama 미연결 시 `template_fallback` 전환과 `warnings` 문구. 확인 못 한 것: Windows/Python 3.9에서의 실제 기동, uvicorn HTTP 응답, 브라우저 동작, Ollama 실제 응답(이 세션에서는 Ollama에 닿을 수 없다).

## 2. 연결 확인 — 질문 1개로 `mode` 보기

`http://localhost:8000/docs` → `POST /chat` → Try it out:

```json
{"message": "이란 핵협상 요즘 어때?", "language": "ko"}
```

또는 PowerShell:

```powershell
$body = @{ message = "이란 핵협상 요즘 어때?"; language = "ko" } | ConvertTo-Json
$t = Measure-Command {
  $r = Invoke-RestMethod -Uri http://localhost:8000/chat -Method Post -ContentType "application/json; charset=utf-8" -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
}
$r.mode; $r.warnings; $r.response; "소요: $($t.TotalSeconds)초"
```

**판정**

| 결과 | 의미 / 다음 행동 |
|---|---|
| `mode: "llm"` | 연결 성공. 3번으로 |
| `template_fallback` + warnings에 `Connection refused` / `Failed to establish` | Ollama가 안 떠 있거나 주소가 다름. `ollama serve` 확인, `OLLAMA_HOST`를 쓴다면 위 0-4번 참고 |
| warnings에 `HTTP 404` | 모델이 설치 안 됨. `ollama pull mistral-nemo` |
| warnings에 `Read timed out` | 180초 초과. 첫 요청은 모델 로딩 때문에 오래 걸리니 한 번 더 시도. 계속되면 `ollama ps`로 모델이 올라왔는지, 메모리 부족은 아닌지 확인 |
| warnings에 `HTTP 500` | Ollama 쪽 오류(메모리 부족 가능성). `ollama serve` 창의 로그 확인 |
| warnings에 `빈 응답` | 모델이 응답은 했지만 텍스트가 빔. 같은 질문 재시도, 그래도 반복되면 기록 |
| `template_fallback`인데 **LLM 실패 warning이 없음** | `verify_model_consensus` import가 실패한 경우(코드상 이때는 warning 없이 템플릿으로 감). uvicorn 창의 import 에러 확인 |

## 3. 응답 품질 테스트 케이스

아래 "기대 검색 결과"는 이 세션에서 같은 코드로 미리 돌려 확인한 값이다. 화면의 📌 이슈 칩, 📊 톤 분포, 출처와 비교해서 다르면 기록한다.

| # | 질문 | 기대 검색 결과 | 좋은 응답 | 실패 신호 |
|---|---|---|---|---|
| A | 이란 핵협상 요즘 어때? | Iran_Nuclear, 기사 0건, Reddit 1건 | "기사 데이터 부족"을 밝힘. Reddit 글이 실제로 이란 관련인지도 확인 | 없는 기사·톤 비율·사건을 서술 |
| B | 미중 무역전쟁 지금 어때? | US_China_Trade, 데이터 0건 | "현재 수집된 데이터로는 확인이 어렵습니다" | 관세율·협상 경과 등을 지어냄 |
| C | 아르헨티나 경제 요즘 어때? | Argentina_Economy, 기사 1건(Reuters "US inflation data…", 중립적 100%) | — (이건 검색 오매칭, 아래 5-4 참고) | 미국 인플레이션 기사를 아르헨티나 근거로 인용 |
| D | 미국 국경 이민 문제 최근 상황은? | US_Mexico_Immigration, 기사 1건(National Review, 비판적 100%) + Reddit 1건 | "비판적 100%"를 인용하고 표본이 1건뿐임을 언급 | 표본 1건으로 "여론이 압도적으로…" 식 일반화 |
| E | 안녕 | 이슈 없음, 데이터 0건 | 이슈 목록을 안내하는 정도 | 임의로 국제정세를 설명 |
| F | 이란이랑 사우디랑 요즘 어때? | Iran_Nuclear만 잡힘(사우디 무시), 기사 0건, Reddit 1건 | 사우디 관련 데이터가 없다고 밝힘 | 사우디 관련 사실을 지어냄 |

**모든 케이스 공통 채점 항목** (기록표에 Y/N):

1. 제공 데이터에 없는 사실을 말했는가 (규칙 1)
2. 톤 분포를 인용했는가 (규칙 2, 데이터가 있을 때만 해당)
3. 언론사/서브레딧 출처를 명시했는가 (규칙 4)
4. 한국어로 자연스럽게 답했는가 (아래 5-1 참고)
5. 근거 없는 "한국에 미치는 영향" 추측이 없는가 (규칙 5)

## 4. 응답 시간 측정

- 첫 요청(모델 로딩 포함)과 바로 다음 요청의 시간을 따로 적는다. 프론트엔드에는 타임아웃이 없어서, 느리면 "생각 중..."이 최대 180초까지 계속 보인다.
- 응답 중 `ollama ps`로 어떤 모델이 올라가 있는지, GPU/CPU 중 어디서 도는지 확인한다.
- 챗봇(mistral-nemo)과 기존 3모델 파이프라인(qwen2.5, exaone3.5)을 번갈아 돌리면 모델이 계속 교체 로딩되므로, 파이프라인을 돌린 직후의 첫 챗봇 응답은 느릴 수 있다.

## 5. 테스트 결과에 따라 손볼 후보 (제안)

확인 등급: **[확인]** = 코드/실행으로 확인, **[추정]** = 코드상 그럴 가능성이 높지만 로컬 응답으로 확인 필요.

1. **[확인] `language`가 프롬프트에 `ko`로 들어간다.** "사용자 언어: ko로 답변하시오"라서 모델이 못 알아듣고 영어로 답할 수 있다. `한국어`/`English` 같은 이름으로 매핑하면 된다. 프론트엔드도 `language: "ko"`로 고정이라 다국어 질문에도 한국어로만 답한다.
2. **[확인] 데이터가 0건이거나 이슈가 없어도 LLM을 호출한다.** `ctx.is_empty()`일 때 LLM을 건너뛰고 안내문만 내면 케이스 A·B·E·F의 할루시네이션 위험이 구조적으로 사라진다. 다만 "데이터가 없다고 말하는 LLM 응답"을 보고 싶다면 이번 테스트 결과를 본 뒤에 결정해도 된다.
3. **[확인] 챗봇 모델이 `mistral-nemo` 고정이다.** 한국어 응답 품질은 `exaone3.5:7.8b`가 나을 가능성이 있다([추정]). 같은 질문 A~F를 모델만 바꿔 돌려 비교하려면 환경변수로 모델을 고르게 하는 한 줄 수정이 필요하다.
4. **[확인] 검색 오매칭이 있다.** 제목에 이슈 키워드가 부분 문자열로 들어 있는지만 보므로, 케이스 C처럼 미국 인플레이션 기사가 "아르헨티나 경제" 근거로 잡힌다(`inflation`이 2차 키워드). 챗봇이 그럴듯하게 인용하면 사용자는 오류를 알아채기 어렵다. 데이터가 늘어나면 더 자주 생긴다.
5. **[확인] 샘플 데이터 4건이 실제 출처처럼 인용된다.** 실데이터를 쌓기 전에 `auto_benchmark_results.csv`의 샘플 행을 분리하거나 표시하지 않으면, 시연 때 가짜 기사가 출처로 나갈 수 있다.
6. **[확인] UI가 `warnings`를 안 보여준다.** 폴백 이유를 화면에서 볼 수 있게 하면 테스트가 훨씬 빨라진다.
7. **[확인] `.env`가 로드되지 않는다.** 챗봇 쪽에 `load_dotenv()`를 추가할지 정해야 한다.
8. **[추정] 팩트체크 노트가 거의 비어 있을 것이다.** `search_google_factcheck`가 언어 코드 `en` 기본값으로 호출되는데 검색어는 한국어 이슈명 첫 단어(예: "미중")다. 이 세션에서도 `factcheck_notes`는 빈 리스트였다. API 키를 넣어도 같은 문제가 남을 수 있다.
