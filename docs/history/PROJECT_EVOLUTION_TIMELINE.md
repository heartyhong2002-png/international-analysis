# 프로젝트 기획 변천 타임라인

이 문서는 국제정세 분석 프로젝트가 왜 "미래 사건 예측"에서 "공급망 리스크 조기경보"로 전환되었는지 보존하기 위한 기록이다. 예전 계획을 실패로 삭제하지 않고, 문제 정의를 검증하고 현실적인 졸업작품 범위로 재설계한 과정으로 남긴다.

## 1단계 국제정세 예측 시스템 구상

초기 목표는 뉴스, 정부 발표, 여론, 경제지표를 수집해 앞으로 어떤 국제정세 이슈가 발생할지 AI가 예측하는 시스템이었다. 이 단계에서 RSS 뉴스 수집, 이슈 태깅, 언어별 LLM 라우팅, 톤 분류, 정부 발표 수집, MySQL 적재, 대시보드 생성, 리포트 자동 생성의 기반이 만들어졌다.

구현된 대표 자산은 다음과 같다.

- `prototype_all_in_one.py`: 뉴스 수집, 이슈 태깅, 출처 편향 태깅, 언어별 LLM 라우팅, 톤 분류
- `scripts/gov_announcements_collector.py`: 정부 공식 발표 수집
- `scripts/issue_data_collector.py`: Wikipedia Pageviews, 경제·제재·무역 신호 수집
- `scripts/build_database.py`: CSV/JSON 수집 결과의 MySQL 통합
- `scripts/generate_dashboard_v2.py`: 대시보드 생성
- `scripts/verify_model_consensus.py`: 3개 모델 앙상블 합의 검증

폐기 판단의 이유는 예측 자체가 졸업작품 범위에서 검증하기 어렵다는 점이었다. 미래 사건은 정답 정의가 모호하고, 실제 사건 발생까지 시간이 필요하며, 사건이 발생하지 않았을 때 시스템이 틀린 것인지 위험이 완화된 것인지 설명하기 어렵다. 국제정세는 외생 변수가 많아 "AI가 맞혔다"는 주장을 방어하기도 어렵다.

## 2단계 대시보드 중심 분석 시스템 정리

예측 시스템의 검증 부담을 낮추기 위해 최종 결과물을 정적·인터랙티브 대시보드로 정리했다. 이 단계에서 이슈별 리포트, PDF·Word 공식 보고서, 일일 분석, 벤치마크 리포트, MySQL 뷰는 최종 결과물이 아니라 대시보드를 뒷받침하는 증거 자료로 재분류했다.

이 결정으로 프로젝트의 중심은 "AI가 미래를 맞힌다"가 아니라 "수집된 신호와 LLM 판단을 근거와 함께 보여준다"에 가까워졌다.

## 3단계 챗봇 서비스 전환 검토 및 보류

한때 사용자가 국제정세 데이터를 대화형으로 질의하는 챗봇 서비스 전환을 검토했다. 관련 프로토타입은 `docs/archive/parked_chatbot_pivot/`에 보존되어 있다.

보류 판단의 이유는 챗봇이 사용성 측면에서는 매력적이지만, 졸업작품의 핵심인 데이터 수집, 검증, 조기 신호 탐지, 대시보드 기반 분석 흐름을 흐릴 수 있었기 때문이다. 챗봇은 향후 확장 기능으로 남기고, 현재 졸업작품의 최종 결과물은 대시보드로 유지한다.

## 4단계 공급망 리스크 조기경보 시스템으로 피벗

최신 방향은 단정적인 미래 예측이 아니라, 관측 가능한 데이터 신호를 바탕으로 위험 증가를 조기에 탐지하는 시스템이다. 목표는 "전쟁이 난다" 또는 "관세가 오른다"를 맞히는 것이 아니라, 뉴스량, 공식 발표, 독립 언론, 현지 여론, 금융·무역 지표에서 평소와 다른 긴장 신호가 포착될 때 사람이 주목할 수 있도록 경보를 제공하는 것이다.

현재 방향의 핵심 개념은 다음과 같다.

- Risk Signal Score: 이슈별 위험 신호 점수
- Signal Gap: 정부·관영 발표와 독립 언론·현지 여론 사이의 괴리
- Alert Level: Normal, Watch, Warning, Critical
- Evidence Coverage: 경보를 뒷받침하는 근거 데이터의 충분도
- Human Review: LLM 판단과 경보 단계에 대한 사람 표본 검수

기존 파일 대부분은 폐기하지 않고 조기경보의 신호 수집·분석·검증 자산으로 재사용한다. 바뀐 것은 데이터의 존재 이유다. 예전에는 "미래 사건을 맞히기 위한 입력"이었다면, 현재는 "위험 신호를 관측하고 경보 근거를 설명하기 위한 입력"이다.

## 5단계 현재 문서 체계

현재 방향의 문서는 `docs/current/`에 따로 둔다. 예전 계획과 보류된 방향은 `docs/history/`와 `docs/archive/`에 남긴다.

- `docs/current/PROJECT_PLAN.md`: 최신 프로젝트 계획
- `docs/current/DATA_COLLECTION_GUIDE.md`: 조기경보 데이터 수집 기준
- `docs/current/VALIDATION_PLAN.md`: 조기경보 검증 계획
- `docs/history/PROJECT_EVOLUTION_TIMELINE.md`: 전체 피벗 타임라인
- `docs/history/PREDICTION_APPROACH_RETIRED.md`: 예측 접근 폐기 사유
- `docs/history/CHATBOT_PIVOT_RETIRED.md`: 챗봇 전환 보류 사유
